The agent activity diagram gives developers one picture of where what work is happening: which agents work on which specification of which project, on which branch and in which folder, and on what system. Agents keep it current by editing one plain YAML file as they work; a person reads it as a picture, arranges it and folds away what they do not need. This page shows its concepts and how they fit together. It is an overview, not the definition: every rule is written in [agent-activity-diagram.md](https://github.com/etalii-adp/etalii.adp/blob/develop/definitions/diagrams/agent-activity-diagram.md), the diagram type is specified in DISL in [agent-activity-diagram.dis](https://github.com/etalii-adp/etalii.adp/blob/develop/definitions/diagrams/agent-activity-diagram.dis), and its file is bound in FBL in [agent-activity-diagram.fbl](https://github.com/etalii-adp/etalii.adp/blob/develop/definitions/diagrams/agent-activity-diagram.fbl).

The source of this page is [`docs/agent-activity-diagram.md` in etalii.adp](https://github.com/etalii-adp/etalii.adp/blob/develop/docs/agent-activity-diagram.md); it describes the definition on etalii.adp's `develop` branch.

In the diagram itself the projects sit in the middle and every other type forms a ring around them, in the order of the picture: specifications, then agents, then locations, then environments. Relations are straight lines without a label.

## The elements

- **Project:** one body of work, such as a repository, with a name and an optional link.
- **Specification:** one piece of specified work in a project. Its status is `pending`, `progressing`, `input-required`, `finished` or `archived`, and is stored as written rather than computed from its tasks. Its tasks are listed beneath it under one heading per status, most recently updated first; archived specifications are hidden unless the person asks to see them.
- **Agent:** one worker on a specification; a thread of a project chat is an agent.
- **Location:** where an agent's work is: a branch, and a folder, the worktree's or `Default` for the repository's main checkout. The pull requests opened from it are listed inside, under a heading that is folded by default.
- **Environment:** a system the work happens on, of the kind local machine, cloud, container, WSL or other. It is one element however many locations use it.

Every element and list item can carry a link, an `http` or `https` address or a path, and clicking its link symbol opens it: an address in the browser, a path in the host.

## The relations

There are four, and nothing else connects: a project to its specifications, a specification to its agents, an agent to its locations, and a location to its environment. Each is a single key on the element at its "one" end, naming the other by its id, so the file itself cannot say that an agent works on two specifications. An agent that changes what it works on changes one line.

## Who writes what

The file is written mostly by agents and read by people.

- **Agents** keep their own entries current: they add themselves when they start on a specification, change the status of a specification or task in place, add their locations and pull requests, and remove themselves when they stop. Each is given a short instruction text that says how, which a host ships beside its examples.
- **The person** arranges the picture. A drag locks an element where it is dropped, a group heading folds or unfolds its group, and a switch shows or hides archived specifications. All of that is kept under `view` in the same file, which agents leave alone.
- **An open diagram follows the file.** When an agent changes it, the picture updates without reopening and the view stays where the person left it; elements that are not locked move a little to make room.

Incomplete pictures are reported as information and never stop the file opening, such as an agent without a specification or a location without an environment.

## The file

One YAML file with the extension `.aad`, registered by an `.adp` file beside it with the origin `etalii/agent-activity-diagram`. It starts with `agent-activity-diagram: 1` and holds up to five lists, `projects`, `specifications`, `agents`, `locations` and `environments`, followed by the person's `view`. Comments, key order and anything the diagram does not read are kept byte for byte, and an edit in ADP changes only the bytes it concerns. The full format, with an example, the reference layout and the instruction text for agents, is in [agent-activity-diagram.md](https://github.com/etalii-adp/etalii.adp/blob/develop/definitions/diagrams/agent-activity-diagram.md).

## Where it stands

The diagram type is specified in DISL 0.4 and FBL 0.4 by this repository's spec [014-agent-activity-diagram](https://github.com/etalii-adp/etalii.adp/tree/develop/specs/014-agent-activity-diagram). The standalone IDE, [etalii-adp/etalii.adp.ide.standalone](https://github.com/etalii-adp/etalii.adp.ide.standalone), is implementing it as its spec-workflow specification `agent-activity-diagram`; no other host implements it yet.
