# Implementation Plan: Site and Home Page

**Branch**: `features/001-site-and-home-page` | **Date**: 2026-09-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-site-and-home-page/spec.md`, plus two review decisions recorded in `.spec-context.json`: the root of `etalii.net` redirects to `/adp` (in the spec as FR-018), and the look and feel (below).

## Summary

Build the site's skeleton and its home page as a static site generated by Astro with its documentation theme Starlight, served by GitHub Pages at `https://etalii.net/adp`. The build writes the site into `dist/adp/` and, beside it, a root `index.html` that redirects to `/adp/` and a root `404.html` that carries the site's navigation, so one Pages site serves the whole domain (FR-001, FR-010, FR-018). A pull request runs the build, an internal link check, WCAG 2.2 AA checks in light and dark schemes, a phone-width and no-script check and a no-third-party check; a push to `develop` runs the same and deploys only if all pass, so a broken build leaves the published site in place (FR-011 to FR-013).

The home page follows the look chosen in review: inspired by aspire.dev and speckit.org, green on dark gray, a logo made of the existing ADP icon (from `etalii-adp/etalii.adp.ide.standalone`) with a display-font wordmark and a catch phrase, and original abstract illustrations. The illustrations are drawn for the site and never presented as the product (principle III). The navigation shows at all times whether a page is in the product part or the documentation part, and it works without scripting at phone width (FR-003, FR-014).

## Technical Context

**Language/Version**: TypeScript 5 and MDX on Node.js 24 LTS

**Primary Dependencies**: Astro (current stable) with `@astrojs/starlight` (current stable); `@fontsource-variable/space-grotesk` for the self-hosted display font. Dev: `@playwright/test`, `@axe-core/playwright`, `linkinator`, `sirv-cli`. Versions are pinned by `package-lock.json`. Research R1 to R4 give the reasons.

**Storage**: files in the repository: MDX pages under `src/content/docs/`, data files under `src/data/` validated by Astro content collections at build time

**Testing**: Playwright with axe-core over every built page (WCAG 2.2 AA in light and dark, phone width without horizontal scroll, scripting disabled, no third-party requests, no cookies); linkinator over `dist/` for internal links; the content-collection schemas fail the build on a host or focus area without its source record

**Target Platform**: GitHub Pages (project build type `workflow`, custom domain `etalii.net`, HTTPS enforced); evergreen browsers, screen readers, scripting optional

**Project Type**: static website

**Performance Goals**: the home page transfers under 500 KB on first load, illustrations included, and renders its text without waiting for any script

**Constraints**: every address and asset under `/adp/`; no third-party requests, no cookies, no analytics; readable without scripting; English only; Apache-2.0 in every footer

**Scale/Scope**: in this feature, 4 pages (home, documentation start, two "coming" section pages) plus the root redirect and the 404 page; the skeleton must take the DEDL reference (spec 002) and the designer catalogue (spec 003, dozens of pages) without changing its navigation model

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked after Phase 1 design.*

| Principle | How this plan meets it | Result |
| --- | --- | --- |
| I. One site for product and documentation | Every page declares its part (`product` or `documentation`); the header shows both parts with the current one marked, and the footer lists every top-level section of both (contract [site-navigation.md](contracts/site-navigation.md)). The home page explains ADP as specialized visualizations for specific tasks, with three focus areas, not as an architecture tool. | Pass |
| II. Sourced, never retyped | IDE host states and links, and the ADP icon, each carry a source record (repository, path, revision, date taken); the content-collection schema fails the build without one, and the home page shows where host states come from and how current they are. Initial host data is taken once by hand in this feature and recorded as such; spec 004 defines the repeatable refresh. See Complexity Tracking. | Pass, with one justified deviation |
| III. Truthful about what exists | A host is shown as available only with a public install; today all four IDE repositories are private, so the home page says "not public yet" instead of linking to a 404. Unbuilt sections are marked "Coming" in the navigation and on their page. Illustrations are abstract artwork, never mock screenshots. | Pass |
| IV. Readable by everyone, anywhere | WCAG 2.2 AA checked by axe on every page in both colour schemes; the navigation needed to reach every page is plain HTML (header part links, breadcrumbs, footer site map), so it works with scripting off at phone width; fonts and assets are self-hosted; search and the theme switcher are left out; no cookies. | Pass |
| V. Maintainable by agents | `npm run build` and `npm run check` are the whole local verification an agent runs before a pull request, and CI runs the same commands; publishing happens only from `develop` through the deploy workflow. | Pass |
| VI. Simplicity | Starlight is justified by current requirements: a documentation part with sidebar navigation, accessible dark and light themes, a 404 route in the site's layout, and the page structure specs 002 and 003 will fill. Astro with it produces static HTML; no server, no database, no search index. | Pass |

Re-check after Phase 1: the design adds no service, no client framework and no third-party resource. The only scripts on a page are Starlight's own enhancements (mobile menu, table-of-contents highlight), each with a no-script path. The gate still passes.

Removed: `index.html` and `package.json` (the GitHub demo files, per the spec's assumptions) and `.github/workflows/proof-html.yml`, which `ci.yml` replaces.

**Structure decision**: one project, a static Astro site with Starlight. Pages written by hand live under `src/content/docs/`; pages generated from data (spec 003's catalogue) live under `src/pages/` and wrap themselves in Starlight's `<StarlightPage>` so they get the same header, breadcrumbs and footer. The build's `dist/` is exactly what GitHub Pages serves at the root of `etalii.net`.
